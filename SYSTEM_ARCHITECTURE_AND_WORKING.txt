================================================================================
1. OVERVIEW
================================================================================

The EEG-Kinova system is a Brain-Computer Interface (BCI) that lets users
control a Kinova Gen3 robotic arm using EEG motor-imagery signals, optionally
fused with OpenCV ball/bar tracking.

Operating modes:
  - Option 5 (EEG-only):  kinova_eeg_controller.py
      Position-based control. EEG predictions trigger go_to_angles moves to
      predefined left/right joint poses. No camera.

  - Option 6 (EEG + OpenCV):  kinova_eeg_opencv_controller.py
      Velocity-based hybrid control. EEG sets direction; OpenCV sets speed.
      Match between EEG and vision → full speed. Mismatch → 50% speed.

  - OpenCV standalone:  OpenCV/track_ball_kinova_test_fixed.py
      Vision-only bar tracking. No EEG.

End-to-end pipeline:
  1. Data Collection       (Unicorn EEG + PyQt5 GUI)
  2. Preprocessing         (Jupyter notebooks per model)
  3. Model Training        (EEGNet / CTNet / FBMSNet)
  4. Real-time Control     (streaming inference → Kinova arm)
  5. Evaluation / Paper    (offline Table I, online Hit/Miss/Gain/Loss plots)

2. CLASS LABEL MAPPING (2-CLASS)
================================================================================

Data collection (dataCollection.py):
  CSV class 1 = "Up (Right Arm)"
  CSV class 2 = "Down (Left Arm)"

After preprocessing (LabelEncoder):
  Model class 0 = Up / Right
  Model class 1 = Down / Left

Robot / OpenCV direction convention (with CALIB_SIGN = +1):
  Class 0 → negative Cartesian X velocity (up on screen)
  Class 1 → positive Cartesian X velocity (down on screen)

Option 5 position targets (kinova_eeg_controller.py):
  Class 0 → RIGHT_ANGLES  (offset pose)
  Class 1 → LEFT_ANGLES   (= ANGLES_INIT)

--------------------------------------------------------------------------------
4.1 DATA COLLECTION (dataCollection.py)
--------------------------------------------------------------------------------

Purpose:
  Record EEG during motor-imagery trials with a PyQt5 GUI.

Hardware:
  - Unicorn Hybrid Black, 8 EEG channels used downstream (17 acquired)
  - 250 Hz sampling via UnicornPy
  - GetAvailableDevices(True) → Unicorn(device) → StartAcquisition(False)

Trial structure per class:
  Baseline → Instruction (color cue) → Stimulus (motor imagery)

2-class labels:
  1 = Up (Right Arm),  2 = Down (Left Arm)

Output:
  EEG_{mode}_trials_{N}_classes_{C}_{timestamp}.csv
  Saved under: data/Subject <N>/<num_classes>_class/

Key columns: trial_index, class_label, phase, timestamp, Ch1…Ch8

--------------------------------------------------------------------------------
4.2 PREPROCESSING (preprocessing_3_class_*.ipynb)
--------------------------------------------------------------------------------

Three notebooks — one per model architecture:

  preprocessing_3_class_EEGNet.ipynb
    Filter: 4–40 Hz Butterworth (filtfilt), z-score
    Output: (N, 1, 8, T)  →  X_train_eegnet.npy, y_train_eegnet.npy, etc.

  preprocessing_3_class_CTNet.ipynb
    Filter: 4–40 Hz Butterworth (filtfilt)
    Output: (N, 8, 250)    →  X_train_ctnet.npy, y_train_ctnet.npy, etc.

  preprocessing_3_class_FBMSNet.ipynb
    Filter: 4–40 Hz broad + 9-band filterbank
    Output: (N, 9, 8, 248) →  X_train_fbmsnet.npy, y_train_fbmsnet.npy, etc.

Label encoding: sklearn LabelEncoder maps CSV labels {1,2} → model {0,1}.

GUI integration (eeg_kinova_control_gui.py):
  - Copies user CSVs to data/2_class/ or data/3_class/
  - Patches notebook paths and runs nbconvert --execute sequentially

--------------------------------------------------------------------------------
4.3 MODEL TRAINING
--------------------------------------------------------------------------------

Scripts:
  EEGNet_new_training.py
  ctnet_training.py
  FBMSNet/train_custom_fbmsnet_updated.py

Output structure (per subject, per model):
  results/Subject_XX/2_class/<MODEL>/run_YYYYMMDD_HHMMSS/
    checkpoints/   *.pth, *_label_map.json
    metrics/       *_summary.json, classification reports
    figures/       confusion matrix, training curves

EEGNet (EEGNet_new_model.py):
  Input:  (batch, 1, 8, T)   Output: logits (num_classes)
  Key params: F1=16, D=2, F2=16, k_temporal=125, dropout=0.5
  Loss: CrossEntropyLoss + class weights
  Optimizer: Adam lr=1e-4, ReduceLROnPlateau, early stopping patience=100

CTNet (ctnet_model.py — CTNetLite for inference):
  Input:  (batch, 8, 250)    Output: (logits, features)
  Key params (Lite): F1=4, D=1, F2=8, 2 transformer layers
  Loss: CrossEntropyLoss + class weights
  Optimizer: AdamW, LR search, gradient clip max_norm=1.0

FBMSNet (FBMSNet/codes/centralRepo/networks.py):
  Input:  (batch, 9, 8, 248) Output: (logits LogSoftmax, features)
  Key params: num_Feat=36, dilatability=8, dropoutP=0.6
  Loss: NLLLoss (LogSoftmax head)
  Optimizer: Adam lr=1e-3

training_artifacts.py — shared helpers for run directories, metrics JSON,
confusion matrices, and figure export.

4.5 REAL-TIME EEG PREDICTOR (real_time_eeg_predictor.py)
--------------------------------------------------------------------------------

Purpose:
  Load a trained checkpoint and run inference on a rolling EEG buffer.

Buffer:
  WINDOW_SAMPLES = 250  (1 second at 250 Hz)

Preprocessing (matches training):
  1. Bandpass 4–40 Hz (Butterworth, filtfilt per channel)
  2. Z-score normalization

Inference:
  predict() → (class_idx, prob_array) or (None, None) if buffer too short
  Default rate in controllers: every 0.5 s (2 Hz)

Model input shapes:
  EEGNet:  (1, 1, 8, T)  — T inferred from checkpoint when possible
  CTNet:   (1, 8, 250)   via CTNetLite
  FBMSNet: (1, 9, 8, 248) — replicated multiband input

Default checkpoint search:
  EEGNet:  outputs/eegnet_new_best.pth
  CTNet:   ctnet_best_model.pth
  FBMSNet: FBMSNet/fbmsnet_best_model.pth

Override with:  --model-path path/to/model.pth

4.6 KINOVA ARM REFERENCE (OpenCV/track_ball_kinova_test_fixed.py)
--------------------------------------------------------------------------------

Standalone vision-only bar tracker. Reference for:
  - Robot TCP connection (Kortex API)
  - ANGLES_INIT initial pose
  - send_vx(linear_x) — Cartesian X velocity only (bar up/down)
  - Workspace corridor: X between start and start − LIMIT_M
  - HSV ball/bar detection, Kalman filter, predictive intercept control

All Option 6 vision math is ported from this file into
kinova_eeg_opencv_controller.py via hardware_config.py.

--------------------------------------------------------------------------------
4.7 OPTION 5: EEG-ONLY CONTROLLER (kinova_eeg_controller.py)
--------------------------------------------------------------------------------

Control paradigm: POSITION-BASED (not velocity).

Flow:
  1. Connect Kinova → go_to_angles(ANGLES_INIT)
  2. Start Unicorn EEG stream (background thread → predictor buffer)
  3. Optional stabilization hold (--stabilization-seconds)
  4. Every PREDICTION_INTERVAL_S = 0.5 s:
     a) predictor.predict() → class 0 or 1 (or None if buffer filling)
     b) Map class to target joint angles:
          Class 0 → RIGHT_ANGLES
          Class 1 → LEFT_ANGLES (= ANGLES_INIT)
     c) If no movement in progress AND target changed:
          Launch async go_to_angles(target, timeout=15 s)
     d) Gating: skip if same target as last command or move still running
  5. Logs predictions and robot X position to logs/kinova_eeg_controller_*.log

Key settings:
  PREDICTION_INTERVAL_S = 0.5
  BOUNDARY_MARGIN_M     = 0.03
  COMMAND_TIMEOUT_S     = 0.9  (watchdog for stale commands)

No camera. No OpenCV. Movement is discrete left/right pose switches.

--------------------------------------------------------------------------------
4.8 OPTION 6: EEG + OPENCV CONTROLLER (kinova_eeg_opencv_controller.py)
--------------------------------------------------------------------------------

Control paradigm: VELOCITY-BASED hybrid fusion.
Position moves (go_to_angles) are DISABLED in the current version.

Flow:
  1. Camera calibration: user clicks 4 corners (TL, TR, BR, BL) → warp
  2. Connect Kinova → go_to_angles(ANGLES_INIT)
  3. Start EEG stream
  4. Main loop at HZ = 60:
     a) Capture frame, perspective-warp to top-down view
     b) HSV detect blue ball, red bar
     c) Kalman filter → ball position (kpx, kpy) and velocity (kvx, kvy)
     d) Vision control law (from track_ball):
          Compute desired bar velocity → vx_cmd (m/s, clamped ±V_MAX)
          opencv_dir = vx_to_direction(vx_cmd):
            vx < -0.02 → class 0 (up)
            vx > +0.02 → class 1 (down)
            else       → None (ambiguous / stop)
     e) EEG prediction every PREDICTION_INTERVAL_S = 0.5 s
        Held for VELOCITY_HOLD_S = 0.8 s between fresh predictions
     f) Hybrid fusion:
          EEG always sets DIRECTION:
            Class 0 → sign = -1.0
            Class 1 → sign = +1.0
          OpenCV sets SPEED MAGNITUDE:
            If opencv_dir available:
              speed = |opencv_vx| clamped to [0.01, V_MAX]
              If EEG class == opencv_dir:  speed × V_FAST_MULT (1.0)  → FAST
              If EEG class != opencv_dir:  speed × V_SLOW_MULT (0.5)  → SLOW
            Else (no vision direction):
              speed = BASE_VX (0.177)
          Final command:
            vx_cmd = CALIB_SIGN × sign × speed
     g) If no EEG (fresh or held): vx_cmd = 0 (robot stops)
     h) Workspace guard: clamp vx_cmd to 0 at X_MIN / X_MAX
     i) send_vx(base, vx_cmd) every loop iteration
  5. HUD overlay: EEG class, OpenCV dir, vx_cmd, match status
  6. Logs to logs/kinova_eeg_opencv_controller_*.log

Key constants:
  V_FAST_MULT = 1.0    (match → full OpenCV speed)
  V_SLOW_MULT = 0.5    (mismatch → half speed)
  BASE_VX     = 0.177  (EEG-only fallback speed)
  DIR_THRESHOLD = 0.02 m/s

Design rationale (see EEG_vs_EEG-OpenCV_Issues.md):
  Position moves conflict with continuous OpenCV velocity correction.
  EEG direction + vision speed gives responsive, visible hybrid behaviour.

8. TROUBLESHOOTING
================================================================================

No model found:
  Train first. Check results/Subject_XX/2_class/MODEL/run_*/checkpoints/
  Or pass --model-path explicitly to controllers.

Robot connection failed:
  Verify ROBOT_IP, network, Kortex API install, arm powered on.

Unicorn not found:
  Install UnicornPy, connect headset, check GetAvailableDevices().

Preprocessing fails:
  Ensure CSVs in data/N_class/. GUI copies files before notebook run.

FBMSNet training:
  Copy .npy files to FBMSNet/data/ (GUI handles this).

Option 6 — arm not moving:
  EEG must be predicting (check buffer fill). Without EEG, vx_cmd=0 always.
  Verify camera calibration and HSV thresholds for ball/bar detection.

Option 6 — arm moves wrong direction:
  Flip CALIB_SIGN in hardware_config.py or check class label mapping.

Option 5 — arm barely moves:
  Position targets (RIGHT_ANGLES) may produce small Cartesian displacement.
  Check logs for measured dx after go_to_angles.

Hybrid mismatch always slow:
  EEG class and OpenCV direction use same convention (0=up/neg, 1=down/pos).
  If consistently mismatched, verify CALIB_SIGN and trained label order.
